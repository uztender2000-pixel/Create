# Інтеграція SendPulse (листи через API)

Проста інтеграція для надсилання транзакційних листів (код підтвердження email,
скидання пароля, доступ до адмін-панелі) через SendPulse REST API.

- Авторизація — **статичний API-ключ** у заголовку `Authorization: Bearer <ключ>`, **без OAuth**.
- Базова адреса API: `https://api.sendpulse.com`.
- Використовуються два методи: `POST /smtp/emails` (відправка) і `GET /user/info` (перевірка ключа).
- Усі секрети беруться лише зі змінних середовища, у коді їх немає.

## Файли

| Файл | Призначення |
|---|---|
| `services/sendpulseClient.js` | сам клієнт: `sendEmail()`, `verifyAuth()`, `isConfigured()`, `SendPulseError` |
| `services/emailClient.js` | загальна функція `sendEmail(to, subject, text)`, яку вже викликає решта сайту; використовує SendPulse, а якщо він не налаштований — SMTP |
| `scripts/sendpulse-test.js` | CLI для перевірки ключа й тестового листа |
| `.env.example` | змінні середовища (лише заповнювачі) |

## Налаштування

1. **Створіть API-ключ.** У SendPulse: *Налаштування → API → API-ключі → Згенерувати*.
   Дайте ключу назву. Поле з обмеженням за IP залиште **порожнім**: на Render (безкоштовний тариф)
   вихідна адреса сервера змінюється, і ключ з обмеженням за IP перестане працювати.
2. **Додайте змінні середовища** на Render (*Environment*) або в локальний `.env`:

   | Змінна | Обов'язкова | Опис |
   |---|---|---|
   | `SENDPULSE_API_KEY` | так | API-ключ |
   | `SENDPULSE_API_FROM_EMAIL` | так | підтверджений відправник (для тесту: `devtest@sendpulseemail.com`) |
   | `SENDPULSE_API_FROM_NAME` | ні | ім'я відправника, наприклад `OllShop` |
   | `SENDPULSE_API_BASE_URL` | ні | за замовчуванням `https://api.sendpulse.com` |

3. **Перевірте ключ:**

   ```bash
   npm run sendpulse:verify
   # або: node scripts/sendpulse-test.js --verify
   ```

   Має з'явитися `✓ Авторизація успішна.`

4. **Надішліть тестовий лист:**

   ```bash
   npm run sendpulse:test -- --to you@example.com
   # з власним текстом:
   node scripts/sendpulse-test.js --to you@example.com --subject "Привіт" --text "Тест" --html "<p>Тест</p>"
   ```

Код завершення скрипта: `0` — успіх, `1` — помилка SendPulse, `2` — неправильні аргументи чи не задана конфігурація.

## Використання в коді

```js
const { sendEmail, verifyAuth, SendPulseError } = require('./services/sendpulseClient');

try {
  const { id } = await sendEmail({
    to: 'client@example.com',                 // рядок, { email, name } або масив
    subject: 'Підтвердження email',
    html: '<p>Ваш код: <b>123456</b></p>',
    text: 'Ваш код: 123456',                  // потрібен хоча б html або text
    // from, fromName, replyTo — необов'язково, переважують змінні середовища
  });
  console.log('Лист прийнято, id:', id);
} catch (err) {
  if (err instanceof SendPulseError) {
    console.error(err.code, err.status, err.message); // ключа в повідомленні немає
  }
}

await verifyAuth(); // кине SendPulseError, якщо ключ невірний
```

Для решти сайту нічого міняти не треба: `services/emailClient.js` сам вибирає SendPulse, коли задані
`SENDPULSE_API_KEY` і `SENDPULSE_API_FROM_EMAIL`. Якщо вони не задані — працює старий SMTP
(`SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`), а якщо немає й його — лист не надсилається, і сайт це коректно обробляє.

> **Важливо про формат.** SendPulse вимагає, щоб `html` у запиті було закодоване в **Base64**.
> Клієнт робить це сам: передавайте в `sendEmail()` звичайний HTML.

## Тестовий (демо) тариф SendPulse SMTP

Нові облікові записи починаються з тестового тарифу SMTP:

- Відправник **`devtest@sendpulseemail.com`** уже підтверджений і активний одразу після реєстрації,
  тому тестовий лист можна надіслати негайно. Саме його вказано як `SENDPULSE_API_FROM_EMAIL` у `.env.example`.
- У демо-режимі SendPulse **сам підміняє відправника** на «SP test <devtest@sendpulseemail.com>»
  і **додає до теми попередження**, що лист призначений лише для розробки — незалежно від значень
  `from` і `subject`, які ви передали. Так і має бути; це не помилка.
- Адреса `devtest@sendpulseemail.com` існує **лише на тестовому тарифі** і зникає, коли ви підтверджуєте
  власний домен і відправника. Після цього, а також на безкоштовному чи платному тарифі, вкажіть
  у `SENDPULSE_API_FROM_EMAIL` власного підтвердженого відправника. Надсилання від непідтвердженого
  відправника повертає **HTTP 422** («Відправник недійсний»).
- На тестовому тарифі є ліміти на загальну кількість листів і на кількість за годину. Конкретні числа
  в коді **не зашито** (вони можуть змінюватися): коли ліміт вичерпано, SendPulse відповідає HTTP 429, і клієнт
  повертає помилку з кодом `RATE_LIMITED`.

## Помилки

Для відповідей, відмінних від 2xx, клієнт кидає `SendPulseError` з очищеним повідомленням (без ключа):

| Код помилки | HTTP | Що означає й що робити |
|---|---|---|
| `CONFIG` | — | не задано `SENDPULSE_API_KEY` або `SENDPULSE_API_FROM_EMAIL` |
| `VALIDATION` | — / 422 | некоректна адреса, порожня тема або текст; запит не відправляється |
| `AUTH` | 401 | ключ невірний чи відкликаний — створіть новий |
| `FORBIDDEN` | 403 | у ключа немає прав або увімкнено обмеження за IP |
| `INVALID_SENDER` | 422 | відправник не підтверджений (див. розділ про демо-тариф) |
| `RATE_LIMITED` | 429 | ліміт чи квоту вичерпано; `err.retryAfter` містить паузу в секундах, якщо SendPulse її повідомив |
| `SERVER` | 5xx | збій на боці SendPulse — повторіть пізніше |
| `NETWORK` | — | не вдалося з'єднатися (таймаут 15 с) |
| `HTTP` | інші | несподівана відповідь; тіло в `err.details` |

Автоматичних повторів клієнт не робить: листи з кодами підтвердження мають дійти один раз, а дублікат гірший за помилку.
Коди `emailClient.js`: `not_configured`, `rate_limited` (для 429) та `api_error` (усе інше); докладна причина лишається в логах Render (`[email] SendPulse: …`).
